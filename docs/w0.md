# W0 품질 시험

실제 아이디어 30~50개로 임베딩 검색과 태그·연결을 시험하고, 직접 평가해 모델을 정한다.

## 준비

1. Node 24 이상에서 `npm install`
2. `.env.example`을 `.env`로 복사하고 `OPENAI_API_KEY`를 적는다. 키와 월 한도는 [설계의 보안](design.md#7-보안)을 따른다.
3. `local/` 폴더에 노트 파일을 둔다. 이 폴더는 커밋되지 않는다.
   - `.txt`: 한 줄이 노트 하나
   - `.json`: 시제품의 `전체 내려받기` 파일. 예시 노트는 빼며, 태그와 연결은 새로 만든다.
4. 선택: `local/questions.txt`에 검색해 볼 질문을 한 줄에 하나씩 적는다.

**노트와 질문의 내용은 OpenAI로 전송된다.**

## 실행

```
npm run w0 -- local/notes.txt --questions local/questions.txt
```

모델을 바꿔 비교할 때는 `--model gpt-6.1-terra`나 `--embedding text-embedding-3-large`를 붙인다. 실행할 때마다 `local/w0/` 아래에 새 폴더가 생기므로 적어 둔 판정은 남는다.

## 평가

1. 결과 폴더의 `report.md`를 열어 `판정` 줄 끝에 `O` 또는 `X`를 적는다.
2. `npm run w0:score -- <report.md 경로>`로 센다.

## 시험 방식

- 노트를 적은 순서대로 하나씩 처리한다. 각 노트의 후보는 앞서 처리한 노트다.
- 후보는 유사도 상위 30개, 태그가 겹치는 노트, 무작위 3개다. 처음 처리하는 노트에는 태그가 없어 태그로 고르는 후보는 없다.
- 노트가 30~50개면 대부분의 노트가 후보에 들어간다. 후보를 고르는 방식의 품질은 이 시험으로 알 수 없고, 보고서의 `비슷한 노트`와 `질문 검색`으로 임베딩을 따로 본다.
- 검색은 임베딩 유사도만 본다. 연결을 따라 넓히는 단계는 W4에서 만든다.
