# W1 적기와 보관

설계의 [만드는 순서](design.md#9-만드는-순서) 중 W1이다. 위에서부터 하나씩 만들고, 테스트가 통과하면 표시한다.

**완료 확인:** 휴대폰에서 적은 노트가 PC와 저장소에 보인다. 연결이 끊긴 채 적은 노트가 나중에 올라간다.

## 작업

- [x] 1. 앱 골격: Vite와 React, CSP, 빈 화면, 빌드
- [x] 2. 노트 형식: ID, `notes/<id>.md` 읽기와 쓰기, `vault.json`
- [x] 3. 기기 저장: IndexedDB의 노트 캐시, 아직 올리지 못한 변경, 설정
- [x] 4. 설정 화면: 저장소, 토큰과 키 입력, `.env` 불러오기, 이 기기에서 지우기
- [x] 5. 적기와 보기: 입력창, 목록, 태그 거르기, 단어 검색, 노트 상세
- [x] 6. GitHub 동기화: 처음 받기, 바뀐 파일 받기, 커밋, 충돌 처리, 다시 보내기, 공개 저장소 거절
    - 2026-11-26 확인: 실제 비공개 저장소에서 `vault.json` 만들기, 노트 올리기·수정·삭제를 커밋 이력으로 보았고, [확인 방법](#작업-6-실제-확인)의 항목은 직접 확인했다. 완전히 빈 저장소에서의 시작은 확인하지 않았다.
- [ ] 7. Pages 배포와 휴대폰·PC 확인
    - 배포 설정(`.github/workflows/pages.yml`)은 만들었다. 배포하고 두 기기에서 확인하면 표시한다([확인 방법](#작업-7-배포와-확인)).

W1에는 태그 자동 부착, 연결, 그래프, 질문, PWA를 넣지 않는다. 연결이 끊긴 채 적는 확인은 앱이 열려 있는 상태에서 한다.

## 작업 6 실제 확인

1. GitHub에 비공개 저장소를 만든다. 비어 있어도 된다.
2. 그 저장소만 대상으로 하는 fine-grained 토큰을 만든다. 권한은 Contents 읽기·쓰기, 만료일을 정한다.
3. `npm run build` 후 `npm run preview`로 열고, 설정에 저장소와 토큰을 넣는다.
4. 지어낸 노트를 적고 저장소에 `vault.json`과 `notes/<id>.md`가 생기는지 본다.
5. GitHub에서 그 노트의 본문을 고친 뒤 앱의 `동기화`를 눌러 반영되는지 본다.
6. 앱과 GitHub에서 같은 노트를 다르게 고쳐 고르는 화면이 나오는지 본다.
7. 앱에서 노트를 지워 저장소에서도 없어지는지 본다.

## 작업 7 배포와 확인

`main`에 push하면 GitHub Actions가 테스트와 빌드를 한 뒤 Pages에 올린다.

1. 이 저장소의 Settings → Pages에서 Source를 `GitHub Actions`로 고른다. 첫 push 전에 한다.
2. `main`에 머지하고 push한다. 코드, 문서, 커밋 이력이 공개된다.
3. Actions 탭에서 `Pages 배포`가 성공하는지 본다.
4. PC와 휴대폰에서 `https://<계정>.github.io/idea-vault-web/`을 열고, 기기마다 설정에 저장소와 토큰을 넣는다.
5. 휴대폰에서 적은 노트가 PC와 저장소에 보이는지 본다.
6. 앱을 열어 둔 채 휴대폰의 연결을 끊고 적은 뒤, 다시 연결해 올라가는지 본다.

## 직접 준비할 것

| 준비 | 필요한 때 |
|---|---|
| 비공개 노트 저장소(이름 제안 `idea-notes`) 만들기 | 작업 6 전 |
| 그 저장소만 대상으로 하는 fine-grained 토큰 (Contents 읽기·쓰기, 만료일) | 작업 6 확인 때 |
| 이 저장소의 push와 Pages 설정 | 작업 7 |

전용 도메인은 설계 제안대로 없이 시작한다. 바꾸려면 작업 7 전에 정한다.
